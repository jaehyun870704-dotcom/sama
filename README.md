# 사마의전 (Sima Yi Chronicle)

『삼국지 조조전』의 턴제 전술 SRPG 모델을 기반으로, 사마의의 생애를 3부 32스테이지로 그리는 캠페인.

> **설계 명제:** 플레이어가 느끼는 *조작의 자유도 자체*가 서사다.
> 상편은 통제할 수 없고 → 중편은 적이 판을 짜고 → 하편은 내가 판을 짠다.

## 상태

| | |
|---|---|
| 단계 | **M0 — 코어 골격 완료.** 기믹 모듈 23종 중 20종이 데이터만으로 표현 가능 |
| 코어 | 결정론적 전투 · 특성 훅 · 이벤트 시스템 · 무르기 · 대화 · 헤드리스 시뮬레이터 |
| 테스트 | 75개 통과 |
| 콘텐츠 | 맵 2 · 스테이지 2 (S1-02 잠입, S1-08 점령 경쟁) |

## 시작하기

```bash
npm install
npm run typecheck        # 타입 검사
npm test                 # 단위 테스트
npm run validate:stages  # 스테이지 데이터 무결성 검증
npm run sim              # 밸런스 시뮬레이션
```

`npm run sim` 출력 예:

```
스테이지 2개 × 200회 시뮬레이션

✅ S1-02 [normal ] 클리어 100.0% | 평균   3.0턴 | 인장2 100.0% | 인장3 100.0%
⚠️  S1-02 [extreme] 클리어 100.0% | 평균   3.0턴 | ...  ← 목표(35.0%) 대비 과도하게 쉬움
✅ S1-08 [normal ] 클리어  11.0% | 평균   4.0턴 | 인장2  11.0% | 인장3  11.0%
⚠️  S1-08 [extreme] 클리어 100.0% | 평균   4.0턴 | ...  ← 목표(30.0%) 대비 과도하게 쉬움
```

⚠️는 콘텐츠 설계 과제를 가리킨다 — 상세는 [개발 로드맵](./docs/tech/개발-로드맵.md)의 "시뮬레이터가 이미 보고한 설계 과제".

## 구조

```

tools/            CI용 데이터 검증 · 밸런스 시뮬레이션
docs/prd/         제품 요구사항
docs/tech/        기술 설계
```

## 핵심 설계 규칙

1. **`packages/core`는 아무것도 import 하지 않는다.** 헤드리스 시뮬레이션이 성립하려면 렌더러·플랫폼 비의존이어야 한다.
2. **스테이지를 추가할 때 코어 코드는 한 줄도 바뀌지 않는다.** 기믹은 트리거/액션 조합으로 표현한다. 코어에 스테이지 ID가 등장하면 설계 위반.
3. **모든 확률은 시드된 RNG 하나에서만 나온다.** 무르기·리플레이·밸런스 QA가 전부 여기서 파생된다.
4. **적 배치는 일반 난이도 기준 1벌만 작성한다.** 극한은 `enemyLevelShift`로 파생시킨다.
5. **피해 감소는 곱연산으로 합성한다.** 덧셈은 무적 유닛을 만든다.
